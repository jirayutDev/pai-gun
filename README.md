# PaiGun

โหวตหาวันว่างร่วมของกลุ่มเพื่อน ที่คิดเป็น **ช่วงวันติดกัน** ไม่ใช่วันเดี่ยว ๆ

## เริ่มใช้งาน

ตอนนี้ข้อมูลเก็บใน Neon Postgres (ดูหัวข้อ "ต่อ Neon Postgres" ด้านล่างถ้ายังไม่มี) — ต้องมี `.env.local` ที่มี `DATABASE_URL` ก่อนถึงจะรันแอปได้จริง (ยังคง `npx tsc --noEmit` และ `npm run build` ผ่านได้แม้ไม่มีค่านี้ เพราะ client ต่อ DB แบบ lazy แต่หน้าเว็บจะ error ทันทีที่ต้องอ่าน/เขียนข้อมูลจริง)

```bash
npm install
cp .env.example .env.local   # แล้วใส่ DATABASE_URL (และ CRON_SECRET ถ้ายังไม่มี)
npm run db:migrate           # สร้างตารางใน Neon ครั้งแรก (ดูหัวข้อ "ต่อ Neon Postgres")
npm run dev
```

เปิด http://localhost:3000

```bash
npm test        # เทสต์อัลกอริทึม 25 เคส
npm run build   # ตรวจว่า build ผ่านก่อน deploy
```

## ลองใช้เส้นทางนี้

1. หน้าแรก กด **ตั้งตี้ใหม่**
2. ขั้น 1 ใส่ชื่อทริปกับช่วงวัน · ขั้น 2 เลือกทริปยาวกี่วัน · ขั้น 3 พิมพ์ชื่อเล่นเพื่อน (วางรายชื่อคั่นด้วยลูกน้ำได้เลย) แล้วติ๊ก **ขาดไม่ได้** ให้คนที่ถ้าไม่ว่างก็ไปไม่ได้
3. กดสร้าง จะเด้งไปหน้าผลโหวตพร้อมกุญแจแอดมินใน URL — **ลิงก์นี้อย่าทำหาย** (เก็บใน localStorage ให้แล้ว และหน้าแรกจะจำไว้)
4. ก็อปลิงก์แชร์ไปเปิดในแท็บใหม่ (หรือมือถือ) เลือกชื่อตัวเอง แล้ว **ลากนิ้วทาบปฏิทิน** เพื่อระบายวันว่าง
5. กลับไปหน้าผลโหวต จะเห็นช่วงที่ดีที่สุด ตัวเลือกสำรอง และช่วง "เกือบได้" ที่ติดคนเดียว

## กฎการออกแบบที่ห้ามพลาดตอนแก้ต่อ

**1. ปฏิทินใช้ `touch-action: pan-y`** ห้ามเปลี่ยนเป็น `none` — ลากแนวนอนคือระบาย ปัดแนวตั้งคือเลื่อนหน้า ถ้าใช้ `none` ปฏิทินจะกินจอจนเลื่อนหน้าไม่ได้

**2. ปฏิทินใช้ `document.elementFromPoint` ตอนลาก** เพราะบนทัชสกรีนมี implicit pointer capture ทำให้ `pointerenter` ไม่ยิงกับช่องอื่นเลย ลบออกแล้วการลากจะทาได้แค่ช่องแรก

**3. ปุ่มย้อนกลับเก็บสแนปช็อตหนึ่งครั้งต่อหนึ่งลาก** ไม่ใช่ต่อช่อง ถ้าเปลี่ยนเป็นต่อช่อง ลาก 20 ช่องจะต้องกดย้อนกลับ 20 ครั้ง

**4. `token` และ `adminKey` ห้ามหลุดลง client component** props ของ client component ถูก serialize ลงใน HTML ที่ทุกคนอ่านได้ `app/t/[slug]/page.tsx` และ `result/page.tsx` จึง map ทีละฟิลด์ ไม่ใช้ spread — อย่าเปลี่ยนเป็น spread

**5. วันที่เก็บเป็น `YYYY-MM-DD` ล้วน** ไม่มี timestamp ในข้อมูลวันว่าง จุดนี้ทำให้ปัญหาโซนเวลาหายไปทั้งหมด อย่าเปลี่ยนเป็น `Date` หรือ `timestamptz`

**6. คนที่กดบันทึกแล้วแต่ปล่อยวันว่างไว้ = ไม่ว่าง (0)** ส่วนคนที่ยังไม่กดบันทึกเลย = ยังไม่ตอบ (0.25) สองอย่างนี้ต่างกัน และเป็นเหตุผลที่คนสำคัญที่ยังไม่ตอบ **ไม่** ทำให้ช่วงถูกตัดออก

## สิ่งที่ต้องทำก่อนใช้งานจริง

**เติมวันหยุดจันทรคติใน `lib/holidays.ts`** — ตอนนี้ใส่ไว้แค่วันหยุดที่ตรึงวันเดิมทุกปี (ปีใหม่ จักรี สงกรานต์ แรงงาน ฉัตรมงคล วันแม่ ปิยมหาราช วันพ่อ รัฐธรรมนูญ สิ้นปี) ส่วนมาฆบูชา วิสาขบูชา อาสาฬหบูชา เข้าพรรษา และวันหยุดชดเชย เปลี่ยนทุกปีตามมติ ครม. ให้เติมใน `LUNAR_AND_EXTRA` แก้ที่เดียวถูกทั้งระบบ ถ้าไม่เติม คะแนน `offDays` จะต่ำกว่าความจริงและระบบจะเชียร์ช่วงที่ต้องลางานโดยไม่จำเป็น

## ต่อ Neon Postgres

ทำครั้งเดียว ก่อนรัน `npm run dev` ครั้งแรกหรือก่อน deploy:

1. เข้า https://console.neon.tech สมัคร/ล็อกอิน (กด "Continue with GitHub" ง่ายสุด)
2. กด **New Project** ตั้งชื่ออะไรก็ได้ (เช่น `paigun`) เลือก region ใกล้ผู้ใช้งานจริง (เช่น Singapore) แพลนฟรีเลือกได้เลยไม่ต้องผูกบัตร
3. Neon สร้างฐานข้อมูล `neondb` ให้อัตโนมัติพร้อมหน้า **Connection Details**
4. คัดลอก connection string ที่ขึ้นต้นด้วย `postgresql://` (ต้องมี `?sslmode=require` ต่อท้าย — ปกติ Neon ใส่ให้อยู่แล้ว) ไปวางเป็น `DATABASE_URL` ใน `.env.local`
5. รัน `npm run db:migrate` — สร้างตาราง `trips` / `participants` / `availability` / `crews` / `crew_members` ให้ครบตาม `lib/db/schema.ts`
6. เสร็จแล้ว `npm run dev` จะอ่าน/เขียนผ่าน Neon ทันที

ข้อควรรู้เรื่องแพลนฟรีของ Neon: compute จะ **หยุดเองอัตโนมัติหลังไม่มีคนใช้ ~5 นาที** (auto-suspend) คำขอแรกหลังจากนั้นจะช้ากว่าปกตินิดหน่อยเพราะต้องปลุกเครื่องขึ้นมาก่อน — เป็นพฤติกรรมปกติของแพลนฟรี ไม่ใช่บั๊ก และเป็นเหตุผลที่ `lib/db/client.ts` เลือกใช้ driver แบบ HTTP (ยิงทีละคำขอ ไม่ถือ connection ค้าง) แทน connection pool

เพิ่ม schema ทีหลัง (เช่นเพิ่มคอลัมน์) ให้แก้ `lib/db/schema.ts` แล้วรัน `npm run db:generate` (สร้างไฟล์ SQL migration ใหม่ใน `drizzle/`) ตามด้วย `npm run db:migrate` (รันจริงกับ DB ที่ชี้อยู่ตอนนั้น)

## ข้อควรระวังเรื่อง OneDrive

โฟลเดอร์นี้อยู่ใต้ OneDrive ซึ่งจะพยายาม sync `node_modules` (หลายหมื่นไฟล์) ทำให้เครื่องหนืดและ sync ค้าง ทางแก้:

- คลิกขวาโฟลเดอร์ `node_modules` แล้วเลือก **Always keep on this device** ปิด หรือ
- ย้ายโปรเจกต์ออกจาก OneDrive ไปที่ `C:\dev\paigun` ซึ่งเป็นวิธีที่แนะนำที่สุด

## ข้อควรระวังเรื่อง Vercel Hobby

- แพลน Hobby อนุญาตให้ใช้เพื่อเรื่องส่วนตัวที่ไม่ใช่เชิงพาณิชย์เท่านั้น นัดเที่ยวกับเพื่อนเข้าเกณฑ์สบาย ๆ
- **บัญชี Hobby ต่อ repo ที่อยู่ใต้ GitHub organization ไม่ได้** ต้องเป็น repo ใต้บัญชีส่วนตัว (personal account) เท่านั้น ถ้า repo ตอนนี้อยู่ใต้ org ให้ transfer มาบัญชีส่วนตัวก่อน หรือสร้าง repo ใหม่ใต้บัญชีส่วนตัวแล้ว push โค้ดไปแทน
- cron ของ Hobby รันได้วันละครั้ง คลาดเวลาได้ ±59 นาที ซึ่งพอสำหรับงานปิดโพลที่เลยเดดไลน์ — ดูหัวข้อ deploy ด้านล่าง

## Deploy ขึ้น Vercel

ทำหลังจากต่อ Neon เสร็จแล้ว (ดูหัวข้อด้านบน) และ `npm run build` ผ่านในเครื่องแล้ว:

1. **push โค้ดขึ้น GitHub** — ต้องเป็น repo ใต้บัญชีส่วนตัว ไม่ใช่ organization (ดูหัวข้อด้านบน) ไฟล์ `.env.local` จะไม่ถูก push ไปด้วยอยู่แล้ว (อยู่ใน `.gitignore`)
2. เข้า https://vercel.com ล็อกอินด้วย GitHub account เดียวกัน
3. กด **Add New → Project** เลือก repo `paigun` ที่เพิ่ง push ไป — Vercel จะจับ framework เป็น Next.js ให้เองไม่ต้องตั้งค่า build command
4. ก่อนกด Deploy ให้เปิด **Environment Variables** แล้วใส่ 2 ตัวจาก `.env.local` ของเครื่องนี้:
   - `DATABASE_URL` — connection string จาก Neon
   - `CRON_SECRET` — ค่าเดียวกับใน `.env.local` (ต้องตรงกัน ไม่งั้น cron จะถูกปฏิเสธด้วย 401)
   ใส่ให้ครบทั้ง 3 scope (Production / Preview / Development) จะได้ทดสอบผ่าน preview URL ได้ด้วย
5. กด **Deploy** รอ build เสร็จ (ควรผ่านเพราะ build ในเครื่องผ่านมาแล้วด้วยขั้นตอนเดียวกัน)
6. เข้า production URL ที่ได้ ลองสร้างทริปทดสอบหนึ่งอันเพื่อยืนยันว่าอ่าน/เขียน Neon ได้จริง (คำขอแรกอาจช้าหน่อยเพราะ Neon compute ต้องตื่นจาก auto-suspend)
7. เช็คว่า cron ติดตั้งจริง: ไปที่ project ใน Vercel → แท็บ **Cron Jobs** ควรเห็น `/api/cron/close` ตั้งไว้วันละครั้งตาม `vercel.json` (ถ้าไม่เห็น ลอง redeploy อีกครั้ง — Vercel อ่าน `vercel.json` ตอน build)
8. อยากทดสอบ cron เองก่อนถึงเวลาจริง: `curl -H "Authorization: Bearer <CRON_SECRET>" https://<โดเมนจริง>/api/cron/close`

หลังจากนี้ทุกครั้งที่ push โค้ดใหม่ขึ้น branch หลัก Vercel จะ build และ deploy ให้อัตโนมัติ
